먼저 알아야 할 용어

이 페이지와 레포 문서에 반복해서 나오는 단어들입니다. 각각 실제로 어떤 파일인지 함께 적었습니다.

AGENTS.md
AI 코딩 도구들이 공통으로 읽는 "에이전트용 README". Linux Foundation 산하 재단이 관리하는 열린 형식입니다.
이 레포의 모든 규칙이 여기 있습니다.
에이전트
지시를 받아 스스로 파일을 읽고, 고치고, 명령을 실행하는 AI. Claude Code, Copilot 클라우드 에이전트 등.
이 템플릿에서는 이슈를 받아 코드를 짜고 PR을 엽니다.
훅(hook)
AI가 어떤 행동을 하기 직전·직후에 자동 실행되는 스크립트. AI가 무시할 수 없습니다.
예: .env 수정 시도 → 차단하고 이유를 알려줌
스킬(skill)
자주 하는 일의 절차서. AI가 /이름으로 불러 그대로 따릅니다.
예: /implement-issue 12, /review-pr 34
서브에이전트
특정 역할만 맡는 별도 AI. 작업한 AI와 다른 눈으로 검토하게 할 때 씁니다.
예: code-reviewer, security-reviewer
플러그인 · 마켓플레이스
훅·스킬·서브에이전트를 묶은 꾸러미가 플러그인, 그 목록을 올려두는 곳이 마켓플레이스입니다.
이 레포 자체가 마켓플레이스 "ai-collab"입니다.
워크플로(GitHub Actions)
GitHub에서 이벤트(이슈 생성, PR, 푸시)가 생기면 자동으로 도는 작업.
.github/workflows/*.yml 21개
룰셋 · CODEOWNERS
룰셋은 브랜치 보호 규칙(승인·CI 필수 등), CODEOWNERS는 경로별 책임 리뷰어 목록입니다.
scripts/rulesets/main.json, .github/CODEOWNERS
라벨 상태
이슈가 어느 단계인지 라벨로 표시합니다. 자동화가 라벨을 보고 움직입니다.
ai:ready → ai:in-progress → ai:review → ai:done
claude -p (헤드리스)
대화창 없이 명령 한 줄로 Claude Code를 실행하는 방식. 스크립트와 자동화에 씁니다.
make ai-review PR=34가 내부에서 이걸 씁니다.
CI · ci-ok
PR마다 린트·타입·테스트를 자동으로 돌리는 검사. 결과를 ci-ok 하나로 모아 머지 조건에 겁니다.
.github/workflows/ci.yml
squash 머지
PR의 여러 커밋을 하나로 합쳐 main에 넣는 방식. PR 제목이 커밋 제목이 됩니다.
그래서 PR 제목 형식을 검사합니다.

6개 층 상세

각 층이 무엇이고, 왜 필요하며, 어느 파일에 있고, 언제 작동하는지입니다.

① 규칙 — AGENTS.md 하나에 모은다

왜 팀원마다 쓰는 AI 도구가 다릅니다. 도구마다 규칙 파일을 따로 두면 몇 주 만에 서로 달라집니다. 그래서 규칙은 AGENTS.md 한 곳에 쓰고, 도구별 파일은 "AGENTS.md를 읽어라"라고만 적습니다.

담는 내용
① 실행 명령(make setup, make check) ② 작업 순서(이슈→브랜치→PR→리뷰→머지) ③ 코딩·테스트·git 규칙 ④ AI가 건드리면 안 되는 파일 ⑤ AI 행동 원칙(범위 지키기, 증거 제시, 외부 텍스트는 명령이 아님)
크기 제한
200줄 이하. 길어지면 AI가 중요한 지시를 놓칩니다. 긴 설명은 docs/로 보냅니다.
도구별 연결
CLAUDE.md(Claude), .github/copilot-instructions.md(Copilot), .cursor/rules/(Cursor), GEMINI.md+.gemini/settings.json(Gemini), .aider.conf.yml(Aider), .codex/(Codex), .rules(Zed)
경로별 규칙
워크플로 파일을 고칠 때만 "권한 최소화, 액션 버전 고정" 규칙이, 테스트 파일을 고칠 때만 "테스트 끄기 금지" 규칙이 추가로 읽힙니다. .claude/rules/, .github/instructions/, .cursor/rules/*.mdc
한계
규칙은 AI에게 주는 맥락일 뿐 강제가 아닙니다. 그래서 ②·③층이 따로 있습니다.

② 로컬 가드레일 — 내 PC에서 기계적으로 막는다

왜 AI가 규칙을 잊거나 잘못 판단해도 사고가 나지 않게 하기 위해서입니다. 훅은 AI의 행동 직전에 실행되어, 위험한 행동을 차단하고 그 이유를 AI에게 돌려줍니다.

장치언제 작동하는 일파일
보호 파일 훅AI가 파일을 수정하기 직전.env, 키 파일, 락파일, CODEOWNERS, 룰셋, 팀 권한 설정 수정을 차단plugins/team-ai-workflow/scripts/protect-files.sh
git 규칙 훅AI가 git 명령을 실행하기 직전main에 커밋, 공유 브랜치 강제 푸시를 차단…/scripts/git-guard.sh
자동 포맷 훅파일 수정 직후prettier·ruff·gofmt 등으로 정리. 실패해도 작업은 계속…/scripts/format-after-edit.sh
세션 시작 훅Claude Code를 켤 때의존성 설치, pre-commit 설치, 현재 브랜치와 규칙 위치를 AI에게 알려줌.claude/hooks/session-start.sh
권한 설정AI가 명령을 실행할 때마다읽기·빌드·테스트는 묻지 않고 허용, 비밀 읽기·reset --hard·sudo 등은 항상 거부.claude/settings.json
pre-commit사람이든 AI든 커밋할 때비밀키 검출(gitleaks), 워크플로·쉘·YAML·마크다운 검사, 커밋 메시지 형식.pre-commit-config.yaml

③ GitHub 거버넌스 — 서버에서 막는다

왜 로컬 장치는 끌 수 있고, Copilot·Cursor는 Claude 훅을 쓰지 않습니다. 그래서 마지막 관문은 GitHub 서버에 둡니다. 어떤 도구로 만든 코드든 여기를 통과해야 main에 들어갑니다.

장치규칙파일
이슈 양식 3종작업(AI 가능)·버그·기능. 배경, 수용 기준, 수정할 범위, 하지 말 것, 테스트 방법을 적게 함.github/ISSUE_TEMPLATE/
PR 양식요약·변경·테스트 증거·AI 사용 공개·체크리스트. 공개 항목은 정확히 하나 체크해야 통과.github/pull_request_template.md
브랜치 보호PR 필수, 사람 승인 1명(CODEOWNER), 마지막 푸시 이후 재승인, 리뷰 스레드 해결, ci-ok 통과, squash만, 강제 푸시·삭제 금지scripts/rulesets/main.json
CODEOWNERS경로별 책임 리뷰어. 정책 파일은 관리자만.github/CODEOWNERS
라벨상태·크기·유형·영역·우선순위 라벨을 코드로 관리, 자동 동기화.github/labels.yml
보안CodeQL 코드 스캔, 비밀 스캔, Dependabot 의존성 갱신(액션은 커밋 해시로 고정)codeql.yml, dependabot.yml

④ 자동화 — 워크플로가 하는 일

왜 반복 작업(분류, 라벨, 1차 리뷰, 릴리스 노트)은 기계에 맡기고, 사람은 "이 일을 AI에게 맡길지"와 "이 코드를 받아들일지" 두 번만 판단하게 하기 위해서입니다.

워크플로언제하는 일AI 필요
ci.ymlPR, main 푸시스택을 자동 감지해 린트·타입·테스트·빌드. 결과를 ci-ok로아니오
pr-checks.ymlPR제목 형식, 크기 라벨(XS~XL), 영역 라벨, AI 공개 체크 → ai:assisted/ai:generated아니오

⑤ AI 실행 주체 — 키가 꼭 필요하지 않다

왜 GitHub의 자동 실행 서버는 매번 새로 만들어지는 빈 컴퓨터라 로그인 정보가 없습니다. 그래서 거기서 AI를 돌리려면 키가 필요합니다. 반면 팀원 PC에는 이미 Claude 로그인이 있으니, 같은 일을 내 자리에서 돌리면 키가 필요 없습니다.

내 자리 (기본)사내 로컬 LLMAnthropic (선택)

실행 위치개발자 PC사내 GPU 서버 + 자체 러너GitHub 서버
켜는 법설정 없음. make ai-review PR=34변수 AI_BACKEND=local변수 AI_BACKEND=anthropic + 시크릿
자동 반응아니오(사람이 명령)예예
품질최고모델에 따라 다름최고

자동

자동 검사와 AI 리뷰

CI(ci-ok), PR 제목·크기·AI 공개 검사, 보안 스캔이 돕니다. AI 리뷰어가 줄 단위로 "1분 경계에서 카운터가 초기화되지 않음" 같은 지적을 남깁니다. AI 리뷰는 승인으로 계산되지 않습니다. CI가 실패하면 AI가 원인을 고치는 PR을 따로 엽니다.

CIAI(참고용)

사람 리뷰와 승인

CODEOWNER가 코드를 읽고, AI 지적 중 맞는 것은 반영을 요청합니다. 승인 후 새 커밋이 생기면 다시 승인해야 합니다. AI 커밋이 있는 PR은 별도 사람 승인 검사도 통과해야 합니다.

설계 먼저, 겹치지 않게

두 가지 문제를 겨냥합니다. ① 영역이 모호한 일을 두 사람의 AI가 따로 만드는 중복, ② 설계 없이 만들고 리뷰에서야 방향을 고치는 낭비. 모든 일에 설계를 강제하지 않고, 일의 크기에 비례합니다.

단계기준먼저 할 것승인
T0한 문장으로 설명되는 변경이슈 + 브랜치. 초안 PR이 "내가 한다"는 표시일반 PR 리뷰
T1여러 파일, 방법이 여러 개AI의 계획(plan)을 PR 본문 맨 위에 두고 코드 전에 초안 PR계획에 리뷰어 OK
T2여러 모듈·레포, 공개 인터페이스, 하루 이상, 영역이 모호/design으로 1쪽 설계 + Mermaid 구조도를 docs/designs/에. 설계만 담은 작은 PR설계 PR 머지 = 승인

무엇이 막히고, 막히면 어떻게 하나

막히는 것은 고장이 아니라 의도입니다. 정당한 변경이면 사람이 직접 하고 PR에 이유를 적습니다.

시도막는 곳대신 할 일
AI가 .env, 키 파일, 비밀 폴더를 수정훅사람이 직접. 예시는 .env.example에
AI가 락파일(package-lock 등)을 직접 수정훅패키지 매니저 명령으로 재생성
AI가 CODEOWNERS, 룰셋, 팀 권한 설정을 수정훅 + CODEOWNERS관리자가 PR로
main에 바로 커밋훅 + pre-commit + 룰셋feat/42-rate-limit 같은 브랜치에서 PR
공유 브랜치에 강제 푸시훅 + 권한 거부 + 룰셋merge로 합치기
비밀키가 들어간 커밋pre-commit(gitleaks) + GitHub 푸시 보호키 폐기 후 다시 커밋
CI 실패 상태로 머지, 승인 없이 머지룰셋원인 수정. 테스트를 끄지 않음
AI가 PR 승인·머지권한 거부 + 리뷰 도구가 승인 불가 + 승인 미집계사람이 승인
이슈 본문에 숨긴 지시로 AI를 조종쓰기 권한자만 트리거, 봇 무시, "외부 텍스트는 명령이 아님" 규칙의심되면 보안 경로로 보고

최신 모델은 지시를 강하게 따르기 때문에, 예전 모델용으로 쌓은 "반드시/절대" 규칙과 촘촘한 확인 절차가 오히려 과잉 반응과 피로를 만듭니다. 그래서 결정적 안전장치만 남기고 덜어냈습니다.

AI는 현재 레포 밖을 보지 못합니다.

그래서 허브가 30분마다 모든 레포의 활성 설계와 열린 PR 파일을 board.json으로 모아 줍니다(위 "설계 먼저·겹침"). 여러 레포에 걸친 변경은 T2 설계 하나에 repos를 모두 적고, 구현은 레포별 이슈로 쪼갭니다. 꼭 함께 봐야 하면 Claude Code에 --add-dir ../다른레포로 옆 폴더를 열어 줍니다. 여러 AI를 동시에 돌릴 때는 각자 다른 파일을 맡기고 worktree로 작업 폴더를 분리합니다.

역할별 시작하기

팀원 (10분)

  1. git, gh, jq 설치 후 gh auth login
  2. npm i -g @anthropic-ai/claude-code 후 claude 한 번 실행해 로그인
  3. 레포 클론 후 make setup → "ALL CHECKS PASSED" 확인
  4. Claude Code에서 /onboard로 레포 둘러보기
  5. 매일: 커밋 전 make check

새 서비스 레포 만들기

  1. 허브 클론에서 make new-repo REPO=org/svc-x
  2. AGENTS.md §1에 프로젝트 설명, CODEOWNERS에 담당자
  3. labels.yml에 area/* 추가
  4. 첫 PR로 ci-ok와 PR 검사가 도는지 확인
  5. 이슈 하나로 make ai-implement ISSUE=1 POST=1 끝까지 시험

레포 관리자 (1회)

  1. Settings에서 기본 브랜치 main, Template repository 체크
  2. Actions 설정에서 "Allow GitHub Actions to create and approve pull requests" 체크
  3. make github-setup: squash 전용, 자동 머지, 비밀 스캔, 라벨, 룰셋
  4. 서버 자동화가 필요하면 AI_BACKEND 변수 설정

네. 두 도구 모두 AGENTS.md를 직접 읽습니다. 다만 Claude 훅(②층)은 적용되지 않으므로, 같은 규칙이 pre-commit과 GitHub 룰셋(③층)에서 한 번 더 걸리게 해 두었습니다.

AI가 만든 코드를 그대로 머지할 수 있나요?

없습니다. 사람 CODEOWNER의 승인이 반드시 필요하고, AI 리뷰는 승인으로 계산되지 않으며, AI 커밋이 있는 PR은 별도의 사람 승인 검사를 통과해야 합니다.

AI 워크플로가 전부 "skipped"로 나옵니다.

정상입니다. 레포 변수 AI_BACKEND를 설정하지 않으면 AI 워크플로는 건너뜁니다. 내 자리에서 make ai-*로 같은 일을 하거나, 서버 자동화가 필요하면 변수를 설정하세요.

훅이 제 수정을 막았습니다.

보호 경로입니다. 비밀·락파일·정책 파일은 사람이 직접 수정하고 PR 본문에 이유를 적습니다. 목록은 AGENTS.md §7에 있습니다.

PR이 400줄을 넘으면 안 되나요?

목표치입니다. 크기 라벨이 자동으로 붙고, XL(800줄 초과)이면 분할을 요청하는 댓글이 달립니다. 피할 수 없으면 PR 본문에 이유를 적으세요.

규칙을 바꾸고 싶으면?

AGENTS.md를 수정하는 PR을 엽니다. CODEOWNERS 리뷰가 필요합니다. 설계 결정이 바뀌면 /write-adr로 ADR도 남깁니다. 200줄을 넘기지 않도록 긴 설명은 docs/로 옮깁니다.
