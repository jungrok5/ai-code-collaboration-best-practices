# ADR-0007: 일의 크기별 설계 단계와 팀 작업 보드

- 상태: Accepted
- 날짜: 2026-10-08
- 설계: [docs/designs/0001](../designs/0001-design-first-and-work-board.md)

## 맥락

AI로 빠르게 구현하면서 두 가지 문제가 자주 발생했습니다. (1) 영역이 모호한 일을 팀원들이 중복으로 작업했고, (2) 설계 없이 구현한 뒤 리뷰에서 방향을 수정했습니다. 그렇다고 모든 일에 설계를 요구하면 문서·승인 병목이 생깁니다.

## 결정

- 일을 T0(한 문장 변경) / T1(plan을 PR 본문에) / T2(1쪽 설계 + 구조도를 먼저 머지)로 구분합니다.
- 설계 front matter의 `areas`와 열린 PR의 변경 파일을 결정적 스크립트(`scripts/designs/board.py`)로 모으고, 허브가 `board.json`으로 게시합니다. AI에게는 한 줄 요약만 제공합니다.
- 겹침은 PR 댓글과 세션 시작 요약으로 알리기만 하고 차단하지 않습니다.

## 결과

- 긍정: 겹침 확인에 드는 LLM 토큰 0, 세션 시작 요약은 세션당 ~2K 토큰. 겹침 알림이 사람 사이의 대화로 이어짐.
- 부정: `areas`를 대충 적으면 겹침을 놓침. 오래된 설계는 21일 뒤 stale 표시로 정리를 유도.
