# ADR-0007: 일의 크기별 설계 단계와 팀 작업 보드

- **상태**: Accepted
- **날짜**: 2026-10-08
- **설계**: [docs/designs/0001](../designs/0001-design-first-and-work-board.md)

## 맥락

AI로 빠르게 구현하다 보니 (1) 영역이 모호한 일을 팀원들이 중복 작업하고 (2) 설계 없이 만든 뒤 리뷰에서 방향을 바로잡는 일이 잦았다. 모든 일에 설계를 강제하면 문서·승인 병목이 생긴다.

## 결정

- T0(한 문장 변경) / T1(plan을 PR 본문에) / T2(1쪽 설계 + 구조도를 먼저 머지)로 나눈다.
- 설계 front matter의 `areas`와 열린 PR의 변경 파일을 결정적 스크립트(`scripts/designs/board.py`)로 모아 허브가 `board.json`으로 게시한다. AI에게는 한 줄 요약만 준다.
- 겹침은 PR 댓글과 세션 시작 요약으로 **알리기만** 한다. 차단하지 않는다.

## 결과

- 긍정: 겹침 확인 비용이 LLM 토큰 0, 세션당 ~2K 토큰. 겹침 알림이 사람 간 대화를 촉발.
- 부정: `areas`를 대충 적으면 놓친다. 오래된 설계는 21일 뒤 stale 표시로 정리를 유도.
