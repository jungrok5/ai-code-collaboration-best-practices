어떤 AI 도구로 작업하든 같은 규칙을 읽고 같은 검사를 통과해야 main에 반영됩니다. 클론 후 make setup 한 번으로 구성되며 API 키 없이 동작합니다. 파란 칸은 사람이 판단하는 지점입니다.

도구별 연결 파일CLAUDE.md · copilot-instructions.md · .cursor/rules · GEMINI.md · .codex · .aider.conf.yml · .rules
경로별 규칙워크플로 · 테스트 · 글과 화면 파일을 수정할 때만 추가로 적용
REVIEW.md · ADR · 설계리뷰 기준, 결정 기록, docs/designs의 1쪽 설계

② 로컬 가드레일 개발자 PC

훅 (플러그인 team-ai-workflow)비밀·정책 파일 수정, main 커밋, 강제 푸시 차단. 수정 직후 포맷과 글·화면 검사
권한 설정읽기·빌드·테스트는 허용, 비밀 읽기 · reset --hard · sudo는 거부
pre-commit · make check사람의 커밋에도 같은 검사. 비밀키, 워크플로, 커밋 메시지

③ GitHub 거버넌스 서버. 어떤 도구로 만든 코드든 통과해야 함

이슈·PR 양식수용 기준과 범위 필수, AI 사용 공개
룰셋 · CODEOWNERSPR 필수, 사람 승인, ci-ok, squash만
보안 스캔CodeQL, 비밀 스캔, Dependabot
이 틀 안에서 작업 진행

④ 이슈에서 머지까지 워크플로 22개와 AI 에이전트가 진행

이슈 등록양식대로 작성
→
AI 분류라벨 제안, 빠진 정보 질문
→
ai:ready 부여AI에 맡길지 결정사람
→
AI 구현worktree, 테스트 먼저, make check
→
초안 PRai:generated, Closes #n
→
CI · AI 리뷰리뷰는 참고용, 승인 아님
→
CODEOWNER 승인받아들일지 결정사람
→
squash 머지이슈 ai:done, 릴리스 노트

이슈 상태는 라벨로 표시합니다(ai:ready → ai:in-progress → ai:review → ai:done, 막히면 ai:needs-human). CI가 실패하면 ci-fix가 수정 PR을 열고, 댓글의 @claude로 질문하거나 수정을 요청할 수 있습니다.

⑤ AI 실행 주체 레포 변수 AI_BACKEND. 없으면 AI 워크플로만 건너뜀

내 자리 (기본)내 claude 로그인으로 make ai-*. 키 없음, 사람이 명령할 때만
사내 로컬 LLMllama.cpp · Ollama + 자체 러너. AI_BACKEND=local
Anthropic구독 토큰 또는 API 키. AI_BACKEND=anthropic

⑥ 여러 레포 배포 허브 1개, 서비스 레포 N개

템플릿 복사make new-repo. 새 레포를 만들 때 1회
플러그인 마켓플레이스claude plugin update로 훅·스킬 일괄 갱신. 선택 스킬은 team-ai-community
조직 설정재사용 워크플로, 조직 룰셋, 조직 .github

팀 운영 장치 AI가 빨라질수록 커지는 병목에 대한 대응

설계 먼저 · 겹침 확인큰 작업은 1쪽 설계 PR부터. 팀 작업 보드가 여러 레포의 설계와 열린 PR을 모아 중복 작업을 알림(토큰 0)
가벼운 하네스사고 비용이 큰 항목만 결정적으로 차단. "이 줄을 지우면 실수하는가"로 규칙을 정리

글과 화면 기준합니다체, 내용 형식 규칙, 팀 디자인 시스템 Clear. 수정 직후 훅 · pre-commit · CI가 검사
